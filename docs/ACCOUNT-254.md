# Account transition prepared for the quota recovery

Release 254 stays local-public. The new workshop, handwriting input, font generator, portrait and print editor do not initialize Supabase or fetch account data. The existing writing-statistics uploader and rank reads are gated while HandLedger254.cloudAllowed() is false. `hand254/account-policy.json` is the authoritative release intent. Date alone MUST NOT enable account or cloud traffic.

A follow-up has been scheduled from October 28, Asia/Shanghai. First verify actual egress allowance and minimal REST availability, rather than interpreting ACTIVE_HEALTHY as a billing/quota result. After confirmed restoration, implement/test the authenticated transition and update the policy in a new release.

The transition must keep the guest IndexedDB untouched until a backup and an explicit ownership decision. A shared device must not silently attach all guest handwriting to whichever account happens to sign in. Partition local handwriting stores by authenticated owner, restore guest access safely on sign-out, and offer a one-time idempotent import. Persisted sample IDs and point fingerprints are stable across repeated imports and color changes. Imported work thumbnails, reference-book images and legacy source images must not be prefetched.

Future data model: owner-scoped glyph samples (vectors and labels), immutable deduplicated writing events (source, exact/estimated count, strokes, active seconds), font files and named collections. Use (owner, local_id) unique keys for idempotent delta upserts. Recompute fine-grained ranks from deduplicated events so the same backup imported on two devices does not count twice. Keep actual and estimated counts separate. Expose only aggregate rank data; raw handwriting, custom font data and collections remain private to the authenticated owner. Do not use user-editable user_metadata for authorization.

Create/validate the schema with the Supabase skill's current workflow at transition time. Every exposed table needs RLS with authenticated ownership predicates for SELECT, INSERT, UPDATE (USING and WITH CHECK) and DELETE, plus explicit minimal grants. Views should use security_invoker. Do not add public security-definer endpoints to bypass RLS. Test two accounts, anonymous access denial, sign-out, repeated import, incremental sync, soft deletion and local-data recovery. Preserve guest backups throughout. No schema or policies have been applied to the live database in release 254.
