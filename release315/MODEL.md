# v315 阶段三：连续笔毫与墨量模型

- brush.js 的 Brush315 分支只接受 settings.engineVersion315===315。旧笔画继续走原函数；金样比对覆盖五种书风，PNG字节不变。
- 32束笔毫身份沿整笔保持，横截面随接触/方向滞后/倾角变化。每束有连续位置、宽度与含墨。笔毫之间未落墨的区域形成留白，不向画布涂白，不调用掩膜或逐帧噪声。
- 模型在原笔迹坐标中运行，Canvas仅做缩放；默认120Hz时间步并限制空间步长。速度单位是“笔径/秒”，不是未经标定的固定屏幕px/ms。
- 速度/方向/笔锋/供墨以时间常数平滑；不使用会过冲的弹簧。预设中的flowResponse控制高速分毫敏感性，不识别用户正在写什么书体。
- 默认高速阈值8笔径/秒、低速退出阈值5.5笔径/秒，均是可调整并随笔画保存的实验参数。未通过真实硬件标定，不应把它们描述为自然常数。
- 飞白门控必须同时满足速度、预设响应、强度、局部含墨不足。饱墨高速仍可完整；强度100不能使慢笔随机飞白，强度0仍保留笔锋宽度和运动响应。
- 总墨池、水润量与32束局部含墨按接触行程消耗。起始墨量是笔画settings的快照，结束墨量保存为endInk315；跨笔画从最后一个未撤销的同补墨epoch笔画读取，不按墙钟时间或网络刷新。
- 浓淡使用笔毫供墨对应的颜色沉积层级，保留原墨色，不靠全笔整体alpha冒充枯润。纸张真实扩散尚未实现。
- 手指/鼠标使用可关闭的速度、曲率与停顿虚拟提按。笔设备只有明确报告的有效压力才进入该分支；诊断区分pen-reported/virtual/fixed。

自动化A–I用例属于合成轨迹验证；实体笔、鸿蒙/Safari、低端机帧预算和完整长时录像仍需真机验收。新引擎先以主书写页的实验开关提供，默认不接管旧作品或所有轻量输入表面。
